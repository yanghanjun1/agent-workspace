# agent-workspace

**bot 会换，工作区不会。**

工作区就是一个目录：一份很小的身份文件、每个生活域一份手册、两条让整套东西不腐烂的日志。
域由 agent 根据你一句话生成，合规与否由断言判定，不靠感觉。

零依赖、零构建、不绑任何厂商。Markdown 加一个纯标准库脚本。

> 规范正文（`SPEC.md`）用英文写，因为它要被引用；长文指南在 `docs/`，中文。

---

## 它解决什么

回答得好但什么都不记得的助手，是个有礼貌的搜索引擎。于是大家把所有背景塞进
system prompt——两周后规则开始不生效，因为文件 800 行、每轮都重发。

三个月后第二个问题来了：没人记得为什么是现在这样。每次大改都要重新推导，
两次推导互相矛盾，助手开始自相矛盾，然后大家怪模型。

换工具时更干脆：全没了。因为它住在某个产品的会话库里，不在文件里。

## 这是什么

| | |
|---|---|
| **一份规范** `SPEC.md` | 七条 MUST，定义一个合规工作区。可引用、可检查。 |
| **一个生成器** `aw new` | 一句需求 → 一个域：手册、两轴、第一条决策记录、能跑的统计脚本。 |
| **一个检查器** `aw check` | 每条 MUST 都是一个会失败的函数。退出码 1 = 真失败了。 |
| **证据** `examples/` | 十条需求进，十个合规工作区出；CI 在三个系统上跑。 |

它**不是** bot、不是插件、不是记忆服务、不是 RAG、不是框架。那些是执行层的选择，
这里是 bot 要读的那一层。

## 五分钟跑起来

```bash
git clone https://github.com/yanghanjun0407/agent-workspace && cd agent-workspace

mkdir -p ../my-workspace
cp templates/AGENTS.zh.md ../my-workspace/AGENTS.md   # 身份文件：只能你自己写

python tools/aw new ca-reading \
  --need "记录这周读了什么、读到哪了" \
  --words "读书/看书/读到哪了/这周读了多少" \
  --lang zh --workspace ../my-workspace --yes

python tools/aw check ../my-workspace
```

最后一条的预期输出：

```
workspace: .../my-workspace
domains:   1

  OK   --   conforming at level 2 (all MUST)

conforming.
```

然后用你手上的任何 agent 打开这个工作区：

```bash
cd ../my-workspace && codex      # 或者 dsh、claude、任何能读目录的 agent
> 今天读了《人类简史》30 页
```

如果它自己去翻了 `ca-reading/SKILL.md`，这个域就是通的。没翻，八成是 `description`
里的话和你的说法对不上——改描述，不要改别处。`aw verify ca-reading` 会带你走验收三问。

## 三层

```
身份层   AGENTS.md        每轮注入，很小，只写路由
   │  按你真正会说的词路由
   ▼
手册层   ca-*/SKILL.md    按需加载，可以长，装操作和口径
   │  干活时读写
   ▼
记忆层   事件日志 · 决策日志 · CURRENT.md
```

`WHY.md` 讲每层回答哪个问题、代价是什么。短版：身份文件是一条**预算定律**（每轮重发，
所以只许放"每轮都必须成立"的东西）；两条日志是"记得住"和"一直正确"之间的差别。

## 七条规则

| | 规则 | 一句话 |
|---|---|---|
| **M0** | 一个工作区一个根 | 域永远不是工作区。域会死，工作区只会迁移。 |
| **M1** | 身份只写路由 | ≤200 行、有路由表、不写流程、不写密钥。 |
| **M2** | 域 = 目录 + 手册 | `SKILL.md`、`name` 等于目录名、`description` 说**何时**用。 |
| **M3** | 两轴都要有内容 | 空文件不算轴。 |
| **M4** | 只追加，事实除外 | 历史不可改写；记错的事实就地改对，并留一条更正。 |
| **M5** | 计算落在脚本 | 模型算数，每次结果都不一样。 |
| **M6** | 一事一源 | 两份规则 = 一份 + 一个未来的矛盾。 |

每条的理由在 `SPEC.md`，包括哪些机器能查。M4b 机器查不了，规范里就直说查不了。

## 可移植性

判据是机械的，不是愿景：

> **一个工作区能移植到某个 harness，当且仅当那个 harness 能以工作区为工作目录启动，
> 并读取根目录的一个文件。**

所以没有"安装"这一步。`cd 工作区 && agent`——agent 是进程，不是场所。没有工作目录的
harness（网页版对话）是另一档，`PORTABILITY.md` 写明那一档会坏在哪、哪些纪律会降级。

---

## 代价（诚实说）

- **身份文件你自己写一次。** 它说助手是谁、归谁管；让 agent 写自己的岗位说明书，
  它一定会写一份自己满意的。`aw new` 拒绝在工作区外运行，同一个道理。
- **两条日志你得写。** 不写是默认选项，而默认选项会在三周内退化成聊天窗口。
- **生成的域要验收，不能只创建。** 三个问题，一条命令。
- **它不更聪明。** 只是不那么健忘——而"不健忘"消掉了大部分你以为是模型的问题。
